# EC2 (Elastic Compute Cloud)

> **AWS's flagship virtual machine service. Choose the right family, the right pricing model, the right placement, and you've already answered half the exam. Built on the Nitro System (Nitro Cards + lightweight hypervisor), with Graviton (ARM), x86 (Intel / AMD), GPU, and ML-accelerator (Inferentia / Trainium) options.**

Maps to: **Domain 2.5 — Design high-performance architectures**, **Domain 1.3 — Reliable / resilient architectures**, **Domain 2.6 / 3.5 — Cost optimization**

---

## Overview

- Resizable compute in the cloud — provision a virtual server (instance) in seconds
- Charged per **second** (Linux) or **hour** (Windows, RHEL, SUSE) depending on AMI
- Instances live in a **VPC**, a **subnet**, and an **Availability Zone**
- Underlying physical hosts and hypervisor are managed by AWS — you control OS and above
- **Nitro System** powers all current-generation instances: dedicated Nitro Cards offload networking, storage, security, and management; lightweight Nitro Hypervisor; Nitro Security Chip; optional **Nitro Enclaves** for isolated compute

---

## Instance Lifecycle

```
pending → running → (stopping → stopped) → (starting → running) → shutting-down → terminated
                  → hibernating → stopped
```

- **Stop**: shuts down OS, retains EBS root volume, releases public IPv4 (unless EIP)
- **Hibernate**: saves RAM to root EBS volume, faster restart (no boot), preserves processes — root volume must be encrypted and ≤ 150 GB; RAM size limited by family
- **Terminate**: deletes the instance; root EBS volume deleted by default (configurable)
- **Reboot**: stays on the same host, no IP change
- **InstanceInitiatedShutdownBehavior**: `stop` or `terminate` when OS issues a shutdown
- **Termination protection**: blocks `TerminateInstances` API (does NOT block ASG-initiated termination)
- **Stop protection**: blocks `StopInstances` API

## Instance Families

Naming: `<family><generation><attributes>.<size>` — e.g., `m7i.large`, `c8g.4xlarge`, `r7iz.metal-16xl`.

| Family | Workload | Notable types |
|---|---|---|
| **General purpose** | Balanced CPU / memory / network | M7i / M7a (x86), **M8g (Graviton 4)**, T3 / T4g (burstable) |
| **Compute optimized** | CPU-bound (gaming, HPC, batch, ML inference) | C7i / C7a, **C8g**, C7gn (network-optimized) |
| **Memory optimized** | In-memory DB, real-time analytics, large caches | R7i / R7a, **R8g**, X2idn / X2iedn (huge RAM), z1d (high freq) |
| **Storage optimized** | High IOPS, sequential I/O, NoSQL, data warehouse | I4i / **I4g** / I8g (NVMe SSD), D3 / D3en (HDD), Im4gn / Is4gen |
| **Accelerated computing** | GPU, FPGA, ML training/inference | **P5 / P5e (H100 / H200)**, G6 (L4), **Trn2 (Trainium2)**, **Inf2 (Inferentia2)**, F2 (FPGA) |
| **HPC optimized** | Tightly coupled HPC | Hpc7a / Hpc7g (EFA, no hyperthreading) |
| **Mac** | macOS workloads (iOS / macOS build) | Mac1 (Intel), Mac2 (M1), **Mac2-m2 / Mac2-m2pro**, **Mac2-m4 (Apple Silicon)** — bare-metal Dedicated Hosts only, 24-hour minimum |

**Attribute letters**: `g` Graviton, `i` Intel, `a` AMD, `n` network-optimized, `z` high frequency, `d` instance storage NVMe SSD, `e` extra memory, `b` block storage optimized, `flex` flexible CPU.

### Graviton

- AWS's ARM CPUs — best price/performance for most workloads
- **Graviton 2** (M6g, C6g, R6g): ~40% better price-perf than x86
- **Graviton 3** (M7g, C7g, R7g): ~25% better compute, 2× crypto, 3× ML vs Gv2
- **Graviton 4** (M8g, C8g, R8g): ~30% better compute, 40% better DB, 75% better web vs Gv3 — current default for new workloads
- **Graviton 5** (preview): targeted at ML inference and high-throughput services
- Re-architecture / re-compile may be needed; most managed services (RDS, Lambda, Aurora, ElastiCache, OpenSearch, MSK) offer Graviton variants transparently

## Purchase Options

| Option | Commitment | Discount vs OD | When to choose |
|---|---|---|---|
| **On-Demand** | None | 0% | Spiky / short workloads, dev/test |
| **Reserved Instances (RI)** | 1 or 3 years, family + region | up to 72% | Steady-state workloads (legacy; prefer Savings Plans) |
| **Compute Savings Plans** | 1 or 3 years, $/hour commit | up to 66% | Flexible — applies across EC2 family, Region, OS, AND Fargate / Lambda |
| **EC2 Instance Savings Plans** | 1 or 3 years, $/hour commit on a family in a Region | up to 72% | Steady EC2 in a known family / Region |
| **Spot Instances** | None | up to 90% | Fault-tolerant batch, CI/CD, stateless web, ML training |
| **Dedicated Instances** | None or RI/SP | OD or RI/SP rate | Workloads requiring instance-level isolation (no shared hardware) |
| **Dedicated Hosts** | Per-host (OD, 1y, 3y) | Hardware-level | BYOL Windows / Oracle / SQL Server, host-affinity compliance, multi-instance-family sharing |
| **Capacity Reservations** | None (pay OD) | 0% (capacity only) | Reserve capacity in a specific AZ without long-term commitment; combine with SP for discount |
| **Capacity Blocks for ML** | 1 to 182 days | OD-style | Reserve P/Trn GPU capacity in advance (gaming releases, training runs) |

**Scheduled Reserved Instances are deprecated** — do not select on the exam.

### Spot

- Bid implicit at OD price; instances reclaimed when capacity needed (**2-minute warning** via instance metadata + EventBridge)
- **Spot Instance Advisor** — historical interruption rates per instance type, picked offline
- **Rebalance Recommendation** — proactive signal before the 2-minute notice; drain gracefully
- **Spot Fleet**: launch a mix of instance types and AZs targeting a capacity (deprecated for new use; prefer EC2 Fleet)
- **EC2 Fleet** — supports On-Demand + Spot + RI/SP, with allocation strategies:
  - **`price-capacity-optimized`** — current default and best practice; balances low price with low interruption risk
  - `capacity-optimized` — minimize interruption (training jobs)
  - `lowest-price` — cost-only (legacy, higher interruption)
  - `diversified` — spread across pools
- **Spot Blocks** are deprecated — do not select
- Handle interruptions: checkpoint state to S3/EFS, drain ALB target, use lifecycle hooks

### Capacity Reservations

- Reserve capacity in a specific **AZ** (not Region) — guaranteed availability
- Pay On-Demand even when idle; combine with Savings Plans / RIs for discount
- **On-Demand Capacity Reservation (ODCR)** — single-AZ
- **Capacity Reservation Fleet** — across AZs / instance types
- **Capacity Blocks for ML** — pre-purchase GPU capacity (P5/P5en/Trn) for a future date range

## Tenancy

| Tenancy | Hardware shared? | Per-host control? | BYOL? |
|---|---|---|---|
| **Default (shared)** | Yes | No | Limited |
| **Dedicated Instance** | No (your account only) | No | Some |
| **Dedicated Host** | No | Yes — you pick the host | Yes (Windows / Oracle / SQL Server, socket / core BYOL) |

- Dedicated Hosts now support **multiple instance families** and **multiple instance sizes** per host (resource groups via **License Manager**)
- **Host affinity** — instance always restarts on the same host (compliance)
- **License Manager** integrates with Dedicated Hosts for socket-based / core-based BYOL tracking

## EBS & Instance Storage

### EBS volume types (current)

| Type | Use case | Max IOPS / volume | Max throughput | Notes |
|---|---|---|---|---|
| **gp3** | General-purpose SSD (default for new) | 16,000 | 1,000 MiB/s | Independent provisioning of IOPS / throughput from size; cheaper than gp2 |
| **gp2** | Legacy general-purpose SSD | 16,000 | 250 MiB/s | IOPS tied to size (3 IOPS / GiB, burst credits) |
| **io2 Block Express** | Mission-critical, sub-ms latency | **256,000** | 4,000 MiB/s | 99.999% durability; up to 64 TiB; SQL Server, SAP HANA |
| **io1** | Legacy provisioned IOPS | 64,000 | 1,000 MiB/s | Replaced by io2 |
| **st1** | Throughput HDD (big data, log processing) | 500 | 500 MiB/s | Cheap sequential |
| **sc1** | Cold HDD (infrequent access) | 250 | 250 MiB/s | Lowest-cost block storage |

- **Multi-Attach**: io1 / io2 only, max 16 instances in the same AZ, application must coordinate
- **Encryption**: all new volumes encrypted by default; AWS-owned key by default, customer-managed KMS optional
- **Snapshots**: incremental, stored in S3 (you don't see the bucket); cross-Region copy, cross-account share, **Snapshot Archive** for ~75% cheaper long-term, **Recycle Bin** for accidental delete protection
- **Fast Snapshot Restore (FSR)**: pre-warms snapshot blocks so first read isn't slow (cost: per AZ per snapshot)
- **EBS direct APIs**: read snapshot blocks directly, useful for forensics / backup software

### Instance store (ephemeral)

- Physically attached NVMe / SSD on certain families (`d`, `i`, `im`, `is`, `r`-suffixed)
- **Lost on stop, hibernate, or terminate** — not on reboot
- Highest IOPS / throughput; used for cache, scratch, distributed file systems

## AMIs (Amazon Machine Images)

- A template containing: root volume (OS + apps), launch permissions, block-device mapping
- **Sources**: AWS-published (Amazon Linux 2 / 2023, Ubuntu, Windows), AWS Marketplace (paid / BYOL), community (vet carefully), your own
- **Cross-account sharing**: add account ID to launch permissions; for encrypted AMIs, also share the KMS key
- **Cross-Region copy**: `copy-image` produces a new AMI ID in the target Region; re-encrypts with the target Region's KMS key
- **AMI deprecation** — set a deprecation date; deprecated AMIs vanish from list APIs but remain launchable until deletion
- **AMI lifecycle (Recycle Bin)** — recover accidentally deleted AMIs / snapshots within retention window
- **AMI Block Public Access** — Region-level setting that prevents accidental public-sharing of AMIs (recommend ON)
- **EC2 Image Builder** — see [EC2 Image Builder note](ec2-image-builder.md) for golden-image pipelines
- **IMDSv2 default** — newer AMIs default to IMDSv2-required; set explicitly with `--imds-support v2.0` when registering custom AMIs

## Instance Metadata Service (IMDS)

- Available at `http://169.254.169.254/latest/meta-data/`
- **IMDSv2 (session-oriented, token-based)** is the secure standard — required to defeat SSRF attacks
- Get a token (PUT request, max TTL 6 hours), then GET with the `X-aws-ec2-metadata-token` header
- **Enforce IMDSv2**:
  - Instance launch: `--metadata-options "HttpTokens=required,HttpPutResponseHopLimit=2,InstanceMetadataTags=enabled"`
  - AMI registration: `--imds-support v2.0` so launched instances inherit IMDSv2-required
  - Organization-level: SCP that denies `RunInstances` unless IMDSv2 is required
- **Audit**: CloudWatch metric `MetadataNoToken` shows instances still using IMDSv1
- **IAM context key `ec2:RoleDelivery`** restricts which version delivers role credentials
- **Instance tags in IMDS** — surface tags at `/latest/meta-data/tags/` (opt-in)

## Instance Profiles (IAM Roles for EC2)

- An IAM role + an **instance profile** wrapper attached to the instance
- Temporary credentials delivered via IMDS — auto-rotated
- One profile per instance; change with `replace-iam-instance-profile-association` (no reboot)
- Use roles instead of baking long-lived access keys into AMIs / user data

## Networking

### ENIs, ENA, EFA

- **Elastic Network Interface (ENI)** — virtual NIC, can be moved between instances (failover patterns)
- **ENA (Elastic Network Adapter)** — high-throughput driver; up to **800 Gbps** on current Nitro families
- **EFA (Elastic Fabric Adapter)** — kernel-bypass for HPC and ML (MPI, NCCL); only inside a Cluster Placement Group
- **Enhanced networking** (SR-IOV) is automatic on Nitro
- **Maximum bandwidth** per instance — published per type; aggregate cap regardless of how many ENIs you attach

### Placement Groups

| Type | Purpose | Latency | Failure domain |
|---|---|---|---|
| **Cluster** | Tight HPC, low latency, high throughput | < 10 µs | Single AZ — high blast radius |
| **Spread** | Anti-affinity (max 7 instances per AZ) | Normal | Different racks, different hosts |
| **Partition** | Big-data clusters (HDFS, Cassandra, Kafka) | Normal | Up to 7 partitions per AZ; instances in different partitions don't share underlying hardware |

- **Cannot move a running instance into a placement group** (stop → modify → start)
- **Mixing instance types** allowed in Cluster but discouraged
- **Multi-AZ**: Cluster is single-AZ only; Spread and Partition can span AZs

### Elastic IPs

- Static public IPv4 — yours until you release
- **Charge for unattached / unused EIPs** (charged even when attached but instance stopped)
- Prefer **NAT Gateway / ALB / Global Accelerator** for stable ingress; reserve EIPs for cases requiring a fixed source IP (allowlists, DNS that can't be reconfigured)

### Connect

- **SSH** with key pairs (RSA 2048 or **ED25519**) — manage key pairs in Console or **EC2 Instance Connect** for ephemeral keys
- **EC2 Instance Connect** — push a one-time SSH key via API; no need to store private keys. Supports browser-based connect for public instances and **EC2 Instance Connect Endpoint** for private subnets (no bastion / NAT needed)
- **Session Manager** (SSM) — recommended secure remote access: no inbound port 22, no bastion, sessions logged to CloudWatch / S3, IAM-controlled; works on private subnets via VPC endpoints
- **Run Command, Patch Manager, Inventory** — operate at scale via SSM agent

## Status Checks & Auto-Recovery

- **System status** — underlying AWS infrastructure (host hardware, network)
- **Instance status** — OS / network config on the instance
- **EBS status** — attached EBS volumes reachable
- **Auto-recovery** — CloudWatch alarm on `StatusCheckFailed_System` triggers `recover` action: instance starts on new hardware, retains instance ID, EIP, EBS, metadata
- Modern alternative: **Auto Scaling self-healing** — set min/max/desired = 1 with health checks

## EC2 Auto Scaling (high level)

> Detailed scaling features deserve their own note. The high-level pieces SAP-C02 tests:

- **Launch Templates** (preferred over legacy Launch Configurations) — versioned, support all features (Mixed Instance Policies, Spot, T-unlimited)
- **Mixed Instance Policy** — combine On-Demand + Spot, multiple types, allocation strategies (`price-capacity-optimized`)
- **Scaling policies**:
  - **Target tracking** — preferred default ("keep CPU at 50%")
  - **Step scaling** — escalating responses based on alarm magnitude
  - **Predictive scaling** — ML forecasts load and scales preemptively
  - **Scheduled scaling** — known peaks
- **Lifecycle hooks** — pause `Pending:Wait` / `Terminating:Wait` to do bootstrapping or graceful drain
- **Warm pools** — pre-initialized stopped instances for fast scale-out (slow-booting AMIs)
- **Instance refresh** — rolling replacement on AMI / Launch Template update; **Skip Matching** to avoid touching instances already on the new version
- **Health checks** — EC2, ELB, custom (via API)
- **Termination policies** — `default`, `OldestInstance`, `NewestInstance`, `OldestLaunchTemplate`, `AllocationStrategy`
- **Capacity Rebalancing** — proactively replaces Spot instances flagged for interruption
- **Standby state** — take an instance out of rotation without termination

## Stop vs Terminate vs Hibernate

| Action | EBS root | Instance ID | Public IPv4 | RAM | Billing |
|---|---|---|---|---|---|
| **Stop** | Retained | Same on restart | Lost (unless EIP) | Lost | EBS only |
| **Hibernate** | Retained, RAM saved | Same | Lost (unless EIP) | Persisted to root EBS | EBS only |
| **Terminate** | Deleted (default) | Gone | Released | Lost | None |

## Cost Optimization Levers

- Right-size with **Compute Optimizer** (see [Compute Optimizer note](compute-optimizer.md))
- Match workload pattern to purchase option: steady → Savings Plans / RI; spiky → On-Demand; fault-tolerant → Spot
- Use **Graviton** where re-compile possible — 20–40% savings
- **Stop or hibernate** non-prod overnight (Instance Scheduler / EventBridge Scheduler)
- **Snapshot Archive** + **AMI deprecation** + **Recycle Bin** to manage long tail
- **Service Quotas / vCPU-based On-Demand Instance Limits** — request increases proactively for major launches

## Security Hardening

- **IMDSv2 required** (`HttpTokens=required`) — set at launch and via Launch Template defaults; enforce via SCP
- **Disable IPv4 public addressing on subnets** unless intentional
- **Security groups stateful**; **NACLs stateless** — defense in depth
- **Instance profiles** with least-privilege role policies
- **SSM Session Manager** + VPC endpoints — eliminate SSH/RDP exposure
- **Nitro Enclaves** for isolated TEE compute (cryptographic key handling, sensitive data processing)
- **Patch Manager** scheduled patch baselines
- **EC2 Image Builder** for golden, hardened AMIs
- **Inspector** continuous vulnerability scanning (CVEs, network reachability)
- **GuardDuty Runtime Monitoring** (EC2) — eBPF agent for behavioural threat detection

## Exam Tips

- **Workload-to-instance-family mapping is testable** — memorize: M (general), C (compute), R (memory), I/D (storage), P/G/Trn/Inf (acceleration), T (burstable), Hpc (HPC), Mac (macOS)
- **Compute Savings Plans** are the most flexible — apply across EC2 family/Region/OS, plus Fargate, plus Lambda
- **EC2 Instance Savings Plans** lock to a family in one Region; higher discount than Compute SP
- **Capacity Reservations are not discounts** — they're a guarantee of capacity; combine with SP/RI for cost
- **Spot interruption signals** — 2-min warning + Rebalance Recommendation; handle via lifecycle hooks, checkpoints
- **`price-capacity-optimized`** is the current default and best practice for Spot Fleet / EC2 Fleet
- **EC2 Fleet > Spot Fleet** for new designs (broader functionality, including On-Demand + RI mix)
- **Cluster placement group** = single-AZ low latency; **Spread** = anti-affinity, max 7/AZ; **Partition** = big-data clusters with isolated partitions
- **EFA requires a Cluster Placement Group** for full benefit
- **io2 Block Express** for highest-IOPS / sub-ms latency (SQL Server, SAP HANA)
- **gp3 is the default** for new general-purpose volumes — provision IOPS / throughput independent of size
- **IMDSv2 enforcement**: launch flag + AMI flag + SCP; audit with `MetadataNoToken` metric
- **EC2 Instance Connect Endpoint** lets you reach private instances without bastion, NAT, or public IP
- **Auto-recovery** via CloudWatch alarm on `StatusCheckFailed_System`; or use ASG with desired=1 for self-healing
- **Hibernate**: encrypted root EBS, ≤ 150 GB, supported instance families only
- **Dedicated Hosts** are the answer for BYOL Windows / Oracle / SQL Server **and** for "instance must run on the same physical host" (host affinity)
- **Mac instances live on Dedicated Hosts only, 24-hour minimum allocation**
- **Nitro Enclaves** for isolated processing of sensitive data (PCI, HIPAA, key material)
- **Graviton** = best price/perf for most workloads when re-compile is feasible

## Exam Traps

- **Scheduled Reserved Instances are deprecated** — if you see it as an option, it's wrong
- **Spot Blocks are deprecated** — same trap
- **Spot Fleet "lowest-price" is no longer the default** — `price-capacity-optimized` is
- **Termination protection does NOT block ASG-initiated termination** — only direct `TerminateInstances` calls
- **Dedicated Instance ≠ Dedicated Host** — Instance gives instance-level isolation only; Host gives per-host BYOL + affinity control
- **You cannot move a running instance into a Placement Group** — stop, modify, start
- **Cluster Placement Group is single-AZ** — do NOT propose it for multi-AZ HA
- **Capacity Reservations are per-AZ, not per-Region** — call out the AZ explicitly
- **Capacity Reservations bill at On-Demand whether you use them or not** — combine with SP for actual discount
- **EIPs are now charged even when attached to a stopped instance** — don't hoard
- **Instance store is lost on stop / hibernate / terminate** — only safe across reboots
- **Hibernate root volume must be encrypted and ≤ 150 GB**; not all families support it
- **EFA without a Cluster Placement Group** still works as ENA but loses the OS-bypass benefit
- **AMI cross-Region copy re-encrypts with target-Region KMS key** — cross-account-cross-Region sharing needs key policy in both Regions
- **IMDSv1 in old AMIs** can re-introduce SSRF risk — audit `MetadataNoToken` and enforce IMDSv2
- **Session Manager requires SSM agent and an instance profile with `AmazonSSMManagedInstanceCore`** — and either internet egress or VPC endpoints for SSM / SSMMessages / EC2Messages
- **EC2 Auto-Recovery only triggers on `StatusCheckFailed_System` (hardware)** — instance status failures need ASG / manual remediation
- **Reserved Instances do not auto-apply to a different instance family** — use **Compute Savings Plans** for that flexibility
- **Dedicated Hosts now support multiple instance families / sizes** — old material claiming "one size per host" is outdated
